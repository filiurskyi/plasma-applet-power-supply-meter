# Architecture

## Boundaries

```text
package/            everything that ships; this directory is the .plasmoid root
  metadata.json     identity: plugin id, name, version, licence, minimum Plasma
  contents/
    ui/             QML views and settings pages
    code/supply.js  sysfs command and parser (pure JavaScript, unit-tested)
    config/         settings schema (main.xml) and settings page list (config.qml)
po/                 translation template and catalogs (compiled at build time)
scripts/            developer tooling, never shipped
tests/              Python repository tests and Qt Quick Tests, never shipped
build/, dist/       generated by scripts/package.py, git-ignored
```

`scripts/package.py` decides what ships: it copies `package/`, adds the
licence text and compiled translations, and rejects any file that is not on
its allow-list.

## Components

| File | Responsibility |
|---|---|
| `ui/main.qml` | `PlasmoidItem` root. Owns all state (`watts`, `sources`, `onAc`, `drainStreak`, `drainWatts`) and the data source, resolves settings and theme into colours and font, formats translated text, sets `Plasmoid.status`, declares the context menu action. |
| `ui/CompactRepresentation.qml` | The gauge. Purely presentational: takes values through properties and emits `expandRequested(bool)`. It does not use the `Plasmoid` attached object, so tests can create it on its own. |
| `ui/FullRepresentation.qml` | The popup: an optional warning line, a heading and a line per supply. |
| `ui/configGeneral.qml`, `ui/configAppearance.qml` | Settings pages. `cfg_<key>` properties map one-to-one to `main.xml` entries. |
| `code/supply.js` | `COMMAND` (a fixed `grep` over sysfs), `parse()`, which turns its output into `{online, sources, watts, draining, drainWatts}`, and `drainStreak()`, the debounce step. |

## Runtime lifecycle

1. Plasma creates `main.qml` once per widget instance. Each instance has its
   own `Plasmoid.configuration`, so several gauges are independent.
2. The `P5Support.DataSource` ("executable" engine) runs `Supply.COMMAND`
   immediately and then every `intervalSeconds`. The engine starts the
   process asynchronously, so the UI thread never blocks on sysfs.
   - The command is a constant: no user input reaches the shell.
   - `grep -sH .` skips unreadable attributes, so a failing UCSI read shows
     "rating not reported" rather than "no external power".
   - At startup the engine may log "Process … already running" once,
     because it connects the source twice during component creation. This
     is harmless.
3. `onNewData` parses the output. `sources` is only reassigned when it
   actually changed, so the popup and tooltip are not rebuilt on every poll.
   The order of grep's lines is not relied on: `parse()` first groups the
   attributes by supply.
4. Plasma creates and destroys the compact and full representations as the
   widget moves between panel, desktop and tray. They hold no state of their
   own, apart from the `wasExpanded` press latch, so recreating them loses
   nothing.

### Drain warning

The same command also reads `type`, `scope`, `status`, `power_now`,
`current_now` and `voltage_now`, so the warning costs no extra process.

- **Condition.** `parse()` sets `draining` when a supply that is not a battery
  has `online` = 1 and a battery (`type` = `Battery`, `scope` not `Device`,
  so mouse and headset batteries are ignored) reports `status` =
  `Discharging`.
- **Why only `Discharging`.** With charge thresholds a plugged-in battery
  stays at `Not charging` once it reaches the limit, and a full one reports
  `Full`. Both are normal and must not warn.
- **Power.** `drainWatts` sums the discharging batteries: `power_now` (µW)
  if present, otherwise `|current_now × voltage_now|` (µA × µV), otherwise 0,
  in which case the text omits the wattage. `*_now` of USB/UCSI supplies is
  never used; the UCSI source reports a meaningless 5 V there.
- **Debounce.** A PD renegotiation briefly drops the contract and the
  battery may report `Discharging` for one read. `main.qml` keeps
  `drainStreak`, the number of consecutive draining polls capped at
  `Supply.DRAIN_POLLS` (2), and shows the warning only when it reaches it.
  This uses the existing poll; there is no extra timer.
- **Output.** While warning, the arc uses `Kirigami.Theme.negativeTextColor`
  (overriding a custom gauge colour), the tooltip, popup and accessible
  description gain a line, and `Plasmoid.status` becomes
  `NeedsAttentionStatus`, which moves the widget out of the tray's hidden
  area. Otherwise the status is `ActiveStatus`.
- **Setting.** `warnWhenDraining` (default on) controls only the colour and
  the status. The text line is informational and is shown either way.

Why polling: neither Plasma nor UPower exposes the negotiated PD rating.
- UPower's line-power objects only expose `Online`.
- The ksystemstats sensors set the hwmon maximum once and never refresh it.

A `grep` every 2 s is a few milliseconds of CPU. It is the cheapest correct
option without a compiled plugin.

## Configuration

`contents/config/main.xml` is a KConfigXT schema.
- Plasma stores the values per instance in
  `~/.config/plasma-org.kde.plasma.desktop-appletsrc`.
- QML reads them as `Plasmoid.configuration.<key>`.
- Settings pages expose `cfg_<key>` properties. The settings dialog handles
  Apply, Cancel and Defaults through these properties.

Validation happens in three places:
- `<min>`/`<max>` in the schema;
- `from`/`to` on the spin boxes (`tests/test_repository.py` checks that
  these agree with the schema);
- clamping in the gauge.

### Changing settings without losing users' values

- **Never rename or retype a released key.** Add a new key instead.
- **Reading an old value.** Read the new key when it differs from its
  default, otherwise fall back to the old key. Plasma keeps unknown keys in
  the config file, so the old value is still available.
- **One-time conversion.** If one is needed, do it in `main.qml` in
  `Component.onCompleted`:
  - only when the new key still has its default value;
  - write the converted value with `Plasmoid.configuration.newKey = …`;
  - mention it in the release notes.
- **Removing a key.** Remove it from `main.xml` only after at least one
  release in which it is unused.

Do not store credentials in `main.xml`; use the Secret Service (KWallet) via a
native backend if a widget ever needs them. Extra data, cache or runtime
files belong in the XDG directories
(`$XDG_DATA_HOME`, `$XDG_CACHE_HOME`, `$XDG_RUNTIME_DIR`), never inside the
installed package, which must be treated as read-only.

## Localization

- All user-visible strings use `i18n()`, `i18nc()`, `i18np()` or `i18ncp()`.
  Placeholders are used instead of concatenation.
- Numbers are formatted with `toLocaleString(Qt.locale(), …)`.
- The translation domain is `plasma_applet_<plugin id>`. Plasma sets it
  automatically for packaged applets.
- `scripts/package.py` compiles `po/<lang>.po` into
  `contents/locale/<lang>/LC_MESSAGES/plasma_applet_<plugin id>.mo` inside the
  archive.
- `metadata.json` names and descriptions can be translated by adding
  `Name[<lang>]` and `Description[<lang>]` keys.

## Native backends

If a widget ever needs compiled code, ship it separately from the
`.plasmoid`:
- **Option 1:** a QML plugin built with CMake/ECM and installed by a
  distribution package.
- **Option 2:** a D-Bus service.

The KDE Store `.plasmoid` must stay architecture-independent. The QML should
detect a missing backend and show a clear message instead of failing.
